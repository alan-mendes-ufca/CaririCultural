# Requisitos Funcionais Priorizados

Critério usado: requisitos marcados como **Must have** na priorização MoSCoW de [Requisitos Funcionais](Requisitos-Funcionais).

| id | requisito | prioridade |
| --- | --- | --- |
| [RF-001](Requisitos-Funcionais#RF-001) | O sistema deve disponibilizar um catálogo regional unificado de locais turísticos, culturais, gastronômicos, comerciais e de lazer. | Must have |
| [RF-004](Requisitos-Funcionais#RF-004) | O sistema deve permitir pesquisa de locais e eventos por palavras-chave, nome, categoria e cidade. | Must have |
| [RF-006](Requisitos-Funcionais#RF-006) | O sistema deve permitir a filtragem de locais e eventos por categoria e adequação ao público (ex: infantil, famílias). | Must have |
| [RF-007](Requisitos-Funcionais#RF-007) | O sistema deve exibir informações descritivas básicas do local, como resumo contextual, categoria e tipo de experiência. | Must have |
| [RF-008](Requisitos-Funcionais#RF-008) | O sistema deve exibir fotos, mídias e características do ambiente físico dos locais. | Must have |
| [RF-009](Requisitos-Funcionais#RF-009) | O sistema deve exibir horários de funcionamento, status atual (aberto/fechado) e indicar possíveis opções de atividades noturnas. | Must have |
| [RF-010](Requisitos-Funcionais#RF-010) | O sistema deve disponibilizar informações financeiras, incluindo cardápio, faixa de preços, taxas e couvert artístico (quando aplicável). | Must have |
| [RF-011](Requisitos-Funcionais#RF-011) | O sistema deve apresentar dados de localização, trajeto, formas de acesso, opções de transporte e estabelecimentos próximos. | Must have |
| [RF-012](Requisitos-Funcionais#RF-012) | O sistema deve disponibilizar informações específicas sobre a segurança do local e de seu entorno. | Must have |
| [RF-014](Requisitos-Funcionais#RF-014) | O sistema deve indicar de forma clara os recursos de acessibilidade disponíveis no local. | Must have |
| [RF-016](Requisitos-Funcionais#RF-016) | O sistema deve exibir calendário e detalhes, como programações musicais, datas e horários dos eventos cadastrados. | Must have |
| [RF-021](Requisitos-Funcionais#RF-021) | O sistema deve exibir avaliações e comentários públicos deixados por outros visitantes sobre os locais. | Must have |
| [RF-026](Requisitos-Funcionais#RF-026) | O sistema deve gerar e recomendar roteiros elaborados e personalizados de passeios de acordo com o interesse do usuário. | Must have |
| [RF-027](Requisitos-Funcionais#RF-027) | O sistema deve permitir criar, organizar e gerenciar listas de locais que o usuário tem desejo de visitar. | Must have |
| [RF-029](Requisitos-Funcionais#RF-029) | O sistema deve disponibilizar checklists de apoio para acompanhamento das atividades e passeios do usuário. | Must have |
| [RF-030](Requisitos-Funcionais#RF-030) | O sistema deve disponibilizar um assistente virtual conversacional para responder dúvidas de lugares e eventos. | Must have |
| [RF-031](Requisitos-Funcionais#RF-031) | O sistema deve ser capaz de interpretar a intenção de busca do usuário no assistente virtual para retornar as informações ou recomendações mais pertinentes. | Must have |
| [RF-033](Requisitos-Funcionais#RF-033) | O sistema deve permitir acionar o assistente de forma contextualizada, permitindo a continuidade direta de uma pesquisa em andamento. | Must have |
| [RF-034](Requisitos-Funcionais#RF-034) | O sistema deve disponibilizar um módulo para importar e atualizar as informações de locais e eventos a partir de fontes de dados externas. | Must have |
